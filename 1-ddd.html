Domain Driven Design

ออกแบบซอฟต์แวร์โดยให้ Business Domain เป็นหัวใจ — code สะท้อนความเป็นจริงของธุรกิจ ไม่ใช่แค่ database schema

💡 DDD คืออะไร?
แนวคิดที่ Eric Evans เสนอในหนังสือ "Domain-Driven Design" ปี 2003

DDD เป็น วิธีคิด ในการออกแบบซอฟต์แวร์ที่ซับซ้อน โดยให้ Domain (ขอบเขตธุรกิจ) เป็นตัวกำหนดโครงสร้างของโค้ด แทนที่จะออกแบบจาก database หรือ framework

Core Idea: "The domain model and the code should be so closely linked that changing one means changing the other." — แบบจำลองธุรกิจและโค้ดต้องสอดคล้องกันอย่างใกล้ชิด
1

Focus on the Core Domain

ทำความเข้าใจธุรกิจ (Domain) อย่างลึกซึ้ง ทำงานร่วมกับ Domain Expert เพื่อให้ code สะท้อน business logic ที่แท้จริง

2

Ubiquitous Language (ภาษาร่วม)

Developer และ Domain Expert ใช้ภาษาเดียวกัน คำว่า "Order", "Invoice", "Customer" มีความหมายเดียวกันในทุกที่ — ใน code, ในเอกสาร, ในการพูดคุย

3

Model-Driven Design

สร้าง Domain Model (แบบจำลอง) ที่ชัดเจน แล้วแปลง Model นั้นเป็น code โดยตรง — ไม่ต้อง translate ระหว่างชั้น

🗺️ Bounded Context
ขอบเขตที่ Model หนึ่งๆ มีความหมายชัดเจน

ในระบบขนาดใหญ่ คำเดียวกันอาจมีความหมายต่างกันในแต่ละส่วน เช่น "Customer" ในระบบขาย vs ระบบบัญชี vs ระบบส่งของ — ต่างกันมาก Bounded Context คือการกำหนดขอบเขตที่ Model นั้นมีความหมายชัดเจน

ระบบ E-Commerce — แบ่งเป็น 4 Bounded Contexts
Context Map: แต่ละ Bounded Context มี Ubiquitous Language ของตัวเอง — คำว่า "Customer" ในระบบ Order อาจมีแค่ ID และ Address แต่ใน Payment Context อาจมี credit score, payment method ด้วย
🧱 Building Blocks (Tactical Patterns)
ส่วนประกอบที่ใช้สร้าง Domain Model
Entity

Entity

สิ่งที่มี Identity ชัดเจน (ID) และ State ที่เปลี่ยนได้ตามเวลา เช่น Order, Customer, User — แม้ข้อมูลจะเปลี่ยน แต่ยังเป็น object เดิม

Value Object

Value Object

ไม่มี Identity — กำหนดจาก ค่า ของมัน เช่น Money(100, "THB") — ถ้าค่าเท่ากัน ก็เป็น object เดียวกัน, Immutable เสมอ

Aggregate

Aggregate Root

กลุ่มของ Entities + VOs ที่รวมกันเป็นหน่วยเดียว มี Aggregate Root เป็นประตูเดียวในการเข้าถึง — รับประกัน consistency

Repository

Repository

Interface สำหรับ persist และ retrieve Aggregates — ซ่อน Storage detail ไว้ใน Infrastructure ทำให้ Domain ไม่รู้จัก database

Domain Service

Domain Service

Business logic ที่ ไม่เป็นธรรมชาติของ Entity ใดๆ เช่น การคำนวณราคาที่ซับซ้อนซึ่งต้องใช้หลาย Aggregates

Domain Event

Domain Event

เหตุการณ์ที่เกิดใน Domain — "สิ่งที่เกิดขึ้นแล้วในอดีต" เช่น OrderPlaced, PaymentReceived — ใช้สื่อสารระหว่าง Contexts

Entity vs Value Object

คุณสมบัติ Entity Value Object
Identity (ID) ✓ มี ID ชัดเจน ✗ ไม่มี
Mutability ✓ เปลี่ยนได้ ✗ Immutable
Equality เปรียบ ID เปรียบค่า
Lifecycle มี lifecycle ยาวนาน สั้น — สร้างใหม่ทุกครั้ง
ตัวอย่าง Order, Customer, Product Money, Address, Email, DateRange

domain/money.go — Value Object Go 
package domain

import (
    "errors"
    "fmt"
)

// Money เป็น Value Object — ไม่มี ID, Immutable, เปรียบจากค่า
type Money struct {
    amount   int64  // เก็บเป็น satang (หน่วยเล็กสุด) เพื่อหลีก floating point error
    currency string
}

// constructor — สร้าง Money ใหม่เสมอ (ไม่ mutate)
func NewMoney(amount int64, currency string) (Money, error) {
    if amount < 0 {
        return Money{}, errors.New("amount must be non-negative")
    }
    if currency == "" {
        return Money{}, errors.New("currency required")
    }
    return Money{amount: amount, currency: currency}, nil
}

func (m Money) Amount() int64    { return m.amount }
func (m Money) Currency() string { return m.currency }

// Baht แสดงค่าเป็น Baht (amount / 100)
func (m Money) Baht() float64 { return float64(m.amount) / 100 }

// Add คืน Money ใหม่ — ไม่ mutate ตัวเอง
func (m Money) Add(other Money) (Money, error) {
    if m.currency != other.currency {
        return Money{}, fmt.Errorf("currency mismatch: %s vs %s", m.currency, other.currency)
    }
    return Money{amount: m.amount + other.amount, currency: m.currency}, nil
}

func (m Money) Multiply(qty int) Money {
    return Money{amount: m.amount * int64(qty), currency: m.currency}
}

// Equal — Value Object เปรียบเทียบจากค่า ไม่ใช่ pointer
func (m Money) Equal(other Money) bool {
    return m.amount == other.amount && m.currency == other.currency
}

func (m Money) String() string {
    return fmt.Sprintf("%.2f %s", m.Baht(), m.currency)
}
// domain/money.ts — Value Object

// Money เป็น Immutable Value Object — กำหนดจากค่า ไม่ใช่ identity
class Money {
  // amount เก็บเป็น satang เพื่อหลีก floating point error
  constructor(
    readonly amount: number,
    readonly currency: string
  ) {
    if (amount < 0) throw new Error("amount must be non-negative");
    if (!currency) throw new Error("currency required");
  }

  static of(amount: number, currency: string): Money {
    return new Money(amount, currency);
  }

  /** แสดงค่าเป็น Baht (amount / 100) */
  get baht(): number {
    return this.amount / 100;
  }

  /** Add คืน Money ใหม่ — ไม่ mutate */
  add(other: Money): Money {
    if (this.currency !== other.currency) {
      throw new Error(`currency mismatch: ${this.currency} vs ${other.currency}`);
    }
    return new Money(this.amount + other.amount, this.currency);
  }

  multiply(qty: number): Money {
    return new Money(this.amount * qty, this.currency);
  }

  /** Value Object เปรียบเทียบจากค่า */
  equals(other: Money): boolean {
    return this.amount === other.amount && this.currency === other.currency;
  }

  toString(): string {
    return `${this.baht.toFixed(2)} ${this.currency}`;
  }
}

export { Money };
domain/order.go — Aggregate Root Go 
package domain

import (
    "errors"
    "time"
)

// ── Types (Ubiquitous Language) ──────────────────────────────────────────
type OrderID    string
type CustomerID string
type ProductID  string

type OrderStatus string
const (
    StatusPending   OrderStatus = "pending"
    StatusConfirmed OrderStatus = "confirmed"
    StatusShipped   OrderStatus = "shipped"
    StatusCancelled OrderStatus = "cancelled"
)

// ── OrderLine — Entity ภายใน Aggregate ──────────────────────────────────
type OrderLine struct {
    productID ProductID
    name      string
    unitPrice Money
    quantity  int
}

func NewOrderLine(productID ProductID, name string, unitPrice Money, qty int) (OrderLine, error) {
    if qty <= 0 {
        return OrderLine{}, errors.New("quantity must be positive")
    }
    return OrderLine{productID: productID, name: name, unitPrice: unitPrice, quantity: qty}, nil
}

func (l OrderLine) ProductID() ProductID { return l.productID }
func (l OrderLine) Name() string         { return l.name }
func (l OrderLine) Quantity() int        { return l.quantity }
func (l OrderLine) LineTotal() Money     { return l.unitPrice.Multiply(l.quantity) }

// ── Order — Aggregate Root ───────────────────────────────────────────────
// ทุก access ต้องผ่าน Order เท่านั้น — ไม่ไปแตะ OrderLine โดยตรงจากข้างนอก
type Order struct {
    id         OrderID
    customerID CustomerID
    lines      []OrderLine
    status     OrderStatus
    createdAt  time.Time
    events     []DomainEvent // Domain Events รอ publish
}

func NewOrder(id OrderID, customerID CustomerID) *Order {
    o := &Order{
        id:         id,
        customerID: customerID,
        status:     StatusPending,
        createdAt:  time.Now(),
    }
    // ทุกครั้งที่สร้าง Order ใหม่ ให้ raise event
    o.raise(OrderCreatedEvent{
        OrderID:    id,
        CustomerID: customerID,
        OccurredAt: o.createdAt,
    })
    return o
}

// Getters — ข้อมูล read-only สำหรับ outside world
func (o *Order) ID() OrderID           { return o.id }
func (o *Order) CustomerID() CustomerID { return o.customerID }
func (o *Order) Status() OrderStatus    { return o.status }
func (o *Order) Lines() []OrderLine     { return append([]OrderLine{}, o.lines...) } // copy

// AddLine — เพิ่มสินค้า (เฉพาะตอน Pending)
func (o *Order) AddLine(line OrderLine) error {
    if o.status != StatusPending {
        return errors.New("cannot modify non-pending order")
    }
    // ถ้า product ซ้ำ ให้รวม quantity
    for i, l := range o.lines {
        if l.productID == line.productID {
            newQty := l.quantity + line.quantity
            o.lines[i].quantity = newQty
            return nil
        }
    }
    o.lines = append(o.lines, line)
    return nil
}

// Total — คำนวณยอดรวม (Domain logic อยู่ใน Aggregate)
func (o *Order) Total() (Money, error) {
    if len(o.lines) == 0 {
        return Money{}, errors.New("order is empty")
    }
    total, _ := NewMoney(0, "THB")
    for _, l := range o.lines {
        var err error
        total, err = total.Add(l.LineTotal())
        if err != nil {
            return Money{}, err
        }
    }
    return total, nil
}

// Confirm — Business Rule: ต้องมีสินค้าก่อน confirm
func (o *Order) Confirm() error {
    if o.status != StatusPending {
        return errors.New("only pending orders can be confirmed")
    }
    if len(o.lines) == 0 {
        return errors.New("cannot confirm empty order")
    }
    total, err := o.Total()
    if err != nil {
        return err
    }
    o.status = StatusConfirmed
    o.raise(OrderConfirmedEvent{
        OrderID:    o.id,
        Total:      total,
        OccurredAt: time.Now(),
    })
    return nil
}

// Cancel — Business Rule: ไม่ cancel หลังส่งแล้ว
func (o *Order) Cancel(reason string) error {
    if o.status == StatusShipped {
        return errors.New("shipped orders cannot be cancelled")
    }
    if o.status == StatusCancelled {
        return errors.New("order already cancelled")
    }
    o.status = StatusCancelled
    o.raise(OrderCancelledEvent{
        OrderID:    o.id,
        Reason:     reason,
        OccurredAt: time.Now(),
    })
    return nil
}

// Domain Event management
func (o *Order) raise(e DomainEvent) {
    o.events = append(o.events, e)
}

// PopEvents — เอา events ออกเพื่อ publish (clear หลัง pop)
func (o *Order) PopEvents() []DomainEvent {
    evts := make([]DomainEvent, len(o.events))
    copy(evts, o.events)
    o.events = nil
    return evts
}
// domain/order.ts — Aggregate Root

import { Money } from "./money";
import { DomainEvent, OrderCreatedEvent, OrderConfirmedEvent, OrderCancelledEvent } from "./events";

// ── Branded types (Ubiquitous Language) ──
type OrderID    = string & { readonly _brand: "OrderID" };
type CustomerID = string & { readonly _brand: "CustomerID" };
type ProductID  = string & { readonly _brand: "ProductID" };

type OrderStatus = "pending" | "confirmed" | "shipped" | "cancelled";

// ── OrderLine — Entity ภายใน Aggregate ──
class OrderLine {
  constructor(
    readonly productId: ProductID,
    readonly name: string,
    readonly unitPrice: Money,
    public quantity: number
  ) {
    if (quantity <= 0) throw new Error("quantity must be positive");
  }

  get lineTotal(): Money {
    return this.unitPrice.multiply(this.quantity);
  }
}

// ── Order — Aggregate Root ──
// ทุก access ต้องผ่าน Order เท่านั้น
class Order {
  private _status: OrderStatus = "pending";
  private _lines: OrderLine[] = [];
  private _events: DomainEvent[] = [];
  readonly createdAt: Date;

  constructor(
    readonly id: OrderID,
    readonly customerId: CustomerID
  ) {
    this.createdAt = new Date();
    this.raise(new OrderCreatedEvent(id, customerId, this.createdAt));
  }

  get status(): OrderStatus   { return this._status; }
  get lines(): readonly OrderLine[] { return [...this._lines]; }

  addLine(productId: ProductID, name: string, unitPrice: Money, quantity: number): void {
    if (this._status !== "pending") {
      throw new Error("cannot modify non-pending order");
    }
    // ถ้า product ซ้ำ ให้รวม quantity
    const existing = this._lines.find(l => l.productId === productId);
    if (existing) {
      existing.quantity += quantity;
      return;
    }
    this._lines.push(new OrderLine(productId, name, unitPrice, quantity));
  }

  /** Total — Domain logic อยู่ใน Aggregate */
  get total(): Money {
    if (this._lines.length === 0) throw new Error("order is empty");
    return this._lines.reduce(
      (sum, l) => sum.add(l.lineTotal),
      Money.of(0, "THB")
    );
  }

  /** Confirm — Business Rule: ต้องมีสินค้าก่อน confirm */
  confirm(): void {
    if (this._status !== "pending") throw new Error("only pending orders can be confirmed");
    if (this._lines.length === 0) throw new Error("cannot confirm empty order");
    const total = this.total;
    this._status = "confirmed";
    this.raise(new OrderConfirmedEvent(this.id, total, new Date()));
  }

  /** Cancel — Business Rule: ไม่ cancel หลังส่งแล้ว */
  cancel(reason: string): void {
    if (this._status === "shipped")   throw new Error("shipped orders cannot be cancelled");
    if (this._status === "cancelled") throw new Error("order already cancelled");
    this._status = "cancelled";
    this.raise(new OrderCancelledEvent(this.id, reason, new Date()));
  }

  private raise(event: DomainEvent): void {
    this._events.push(event);
  }

  /** popEvents — เอา events ออกเพื่อ publish (clear หลัง pop) */
  popEvents(): DomainEvent[] {
    const evts = [...this._events];
    this._events = [];
    return evts;
  }
}

export { Order, OrderLine, OrderID, CustomerID, ProductID, OrderStatus };

application/order_service.go — Application Service Go 
package application

import (
    "context"
    "fmt"
    "myapp/domain"
)

// PlaceOrderCommand — Input DTO สำหรับ Use Case นี้
type PlaceOrderCommand struct {
    CustomerID string
    Items      []OrderItem
}

type OrderItem struct {
    ProductID string
    Name      string
    UnitPrice int64 // satang
    Quantity  int
}

// PlaceOrderResult — Output DTO
type PlaceOrderResult struct {
    OrderID string
    Total   float64
}

// OrderApplicationService — orchestrates domain objects
// ไม่มี business logic ที่นี่! — แค่ coordinate
type OrderApplicationService struct {
    orderRepo domain.OrderRepository
    publisher domain.EventPublisher
}

func NewOrderApplicationService(
    repo domain.OrderRepository,
    pub domain.EventPublisher,
) *OrderApplicationService {
    return &OrderApplicationService{orderRepo: repo, publisher: pub}
}

func (s *OrderApplicationService) PlaceOrder(ctx context.Context, cmd PlaceOrderCommand) (*PlaceOrderResult, error) {
    // 1. Generate new ID
    orderID, err := s.orderRepo.NextID(ctx)
    if err != nil {
        return nil, fmt.Errorf("generate order id: %w", err)
    }

    // 2. สร้าง Aggregate
    order := domain.NewOrder(orderID, domain.CustomerID(cmd.CustomerID))

    // 3. ใส่สินค้า — business rules อยู่ใน AddLine
    for _, item := range cmd.Items {
        price, err := domain.NewMoney(item.UnitPrice, "THB")
        if err != nil {
            return nil, fmt.Errorf("invalid price for %s: %w", item.ProductID, err)
        }
        line, err := domain.NewOrderLine(
            domain.ProductID(item.ProductID), item.Name, price, item.Quantity,
        )
        if err != nil {
            return nil, fmt.Errorf("invalid line: %w", err)
        }
        if err := order.AddLine(line); err != nil {
            return nil, fmt.Errorf("add line: %w", err)
        }
    }

    // 4. Confirm — business rule ใน Aggregate
    if err := order.Confirm(); err != nil {
        return nil, fmt.Errorf("confirm order: %w", err)
    }

    // 5. Persist
    if err := s.orderRepo.Save(ctx, order); err != nil {
        return nil, fmt.Errorf("save order: %w", err)
    }

    // 6. Publish Domain Events
    events := order.PopEvents()
    if err := s.publisher.Publish(ctx, events); err != nil {
        return nil, fmt.Errorf("publish events: %w", err)
    }

    total, _ := order.Total()
    return &PlaceOrderResult{
        OrderID: string(order.ID()),
        Total:   total.Baht(),
    }, nil
}

func (s *OrderApplicationService) CancelOrder(ctx context.Context, orderID, reason string) error {
    order, err := s.orderRepo.FindByID(ctx, domain.OrderID(orderID))
    if err != nil {
        return fmt.Errorf("find order: %w", err)
    }

    // Business rule อยู่ใน Aggregate.Cancel()
    if err := order.Cancel(reason); err != nil {
        return fmt.Errorf("cancel order: %w", err)
    }

    if err := s.orderRepo.Save(ctx, order); err != nil {
        return fmt.Errorf("save order: %w", err)
    }

    return s.publisher.Publish(ctx, order.PopEvents())
}
สังเกต: Application Service (PlaceOrder) ไม่มี if/else logic ที่เกี่ยวกับ business — ทุก rule อยู่ใน Domain Objects (order.Confirm(), order.Cancel()) Application Service แค่ orchestrate ขั้นตอน
📦 DDD Layers
4 ชั้นของ DDD Application

🖥️ Presentation Layer

HTTP Handlers, gRPC, CLI — รับ input จากผู้ใช้/client แปลงเป็น Commands แล้วส่งให้ Application Layer

↕

⚙️ Application Layer

Application Services — Orchestrates use cases, ไม่มี business logic เอง แค่ coordinate

↕

🏛️ Domain Layer ← หัวใจหลัก

Entities, Value Objects, Aggregates, Domain Services, Domain Events — ไม่ depend ชั้นอื่นเลย

↕

🗄️ Infrastructure Layer

Repositories (PostgreSQL, MongoDB), Email Service, Event Bus — implement interfaces ที่ Domain กำหนด

Dependency Rule: ทุก Layer depend inward — Presentation → Application → Domain ← Infrastructure Domain ไม่ depend ชั้นใดเลย! ทำให้ test ได้ง่ายมาก
