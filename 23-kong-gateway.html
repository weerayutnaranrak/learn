🌐 Kong Gateway คืออะไร?

Kong Gateway คือ API Gateway open-source ที่สร้างบน Nginx + OpenResty (Lua) ทำหน้าที่เป็น "ประตู" กลางระหว่าง client กับ upstream services — จัดการ cross-cutting concerns ทั้งหมดในที่เดียว ไม่ต้องเขียนซ้ำใน service แต่ละตัว

💡
ทำไมต้องมี API Gateway?
ใน Microservices แต่ละ service ต้องการ auth, rate limiting, logging เหมือนกัน — ถ้าเขียนเองทุก service จะซ้ำซ้อนมาก Kong รวม logic เหล่านี้ไว้ที่ gateway ชั้นเดียว

📦 Core Concepts — 5 Building Blocks

Kong ใช้ 5 objects หลักในการ config ทุกอย่าง เข้าใจ 5 ตัวนี้ก็เข้าใจ Kong แล้ว 80%

🔌
Service
ตัวแทน upstream service ที่ Kong จะ forward request ไป — เก็บ URL ของ backend

ตัวอย่าง: host: order-service, port: 8080, path: /
  • 1 Service = 1 upstream application
  • มี Route หลายตัวชี้มาได้
  • ตั้ง connect/read timeout ได้
🗺️
Route
กำหนดว่า request แบบไหนจะถูก match แล้วส่งไป Service ไหน — match ด้วย path, host, method, header

ตัวอย่าง: paths: [/api/orders], methods: [GET, POST]
  • Route → Service (many-to-one)
  • regex path matching รองรับ
  • strip_path ตัด prefix ออกได้
🧩
Plugin
เพิ่ม functionality ให้ Kong — ติด plugin ที่ระดับ Global / Service / Route / Consumer ได้

ตัวอย่าง: rate-limiting, jwt, cors, request-transformer
  • รันในลำดับ priority
  • enable/disable ได้ทันที
  • เขียนเองด้วย Lua หรือ Go
👤
Consumer
ตัวแทน "ผู้เรียกใช้" API — อาจเป็น user, application, หรือ service อื่น เก็บ credentials และ metadata

ตัวอย่าง: consumer mobile-app มี API key และ rate limit ของตัวเอง
  • ผูก credentials (JWT/API Key)
  • ติด plugin เฉพาะ consumer ได้
  • ดู usage ต่อ consumer ได้
⚖️
Upstream & Target
กลุ่ม backend servers สำหรับ load balance — Upstream = กลุ่ม, Target = server แต่ละตัว

ตัวอย่าง: upstream order-svc มี 3 targets
  • health check active/passive
  • weight-based routing
  • round-robin / least-conn / hash
🏢
Workspace (Enterprise)
แบ่ง Kong ออกเป็น tenants — แต่ละ team มี Services/Routes/Plugins แยกกัน ไม่ปนกัน

ใช้ใน: องค์กรที่มีหลาย team share Kong instance เดียว
  • RBAC ต่อ workspace
  • แยก Admin API scope
  • Enterprise feature เท่านั้น

🚀 Deployment Modes

Kong มี 3 deployment modes — เลือกตามความต้องการด้าน scalability และ operational complexity

🗄️
DB Mode
Traditional
เก็บ config ใน PostgreSQL — Admin API เขียนลง DB ตรง DP อ่าน config จาก DB
  • เปลี่ยน config ได้ทันทีไม่ต้อง restart
  • Admin GUI (Kong Manager) ทำงานได้เต็มที่
  • เหมาะกับ monolith → microservices transition
📄
DB-less Mode
Declarative
Config อยู่ใน YAML/JSON file — load ตอน startup ไม่ต้องการ DB เลย
  • ไม่มี DB = ไม่มี single point of failure
  • Config เป็น code (GitOps friendly)
  • เหมาะกับ K8s และ immutable infra
🔀
Hybrid Mode
Enterprise / Best of Both
CP เก็บ config ใน DB, DP รัน stateless รับ config ผ่าน mTLS cluster
  • DP ไม่ต่อ DB โดยตรง — ปลอดภัยกว่า
  • DP scale ได้อิสระ scale CP แยกต่างหาก
  • เหมาะกับ multi-region / multi-cloud

📄 Config: Admin API & decK

Kong ตั้งค่าได้ 2 วิธีหลัก — Admin API (imperative, runtime) และ decK (declarative, GitOps)

Admin API — ตั้งค่าแบบ imperative

ตั้งค่า Service + Route + Plugin ผ่าน Admin API bash 
# 1. สร้าง Service (upstream backend)
curl -s -X POST http://localhost:8001/services \
  -d name=order-service \
  -d url=http://order-service:8080

# 2. สร้าง Route ผูกกับ Service
curl -s -X POST http://localhost:8001/services/order-service/routes \
  -d "paths[]=/api/orders" \
  -d "methods[]=GET" \
  -d "methods[]=POST" \
  -d strip_path=false \
  -d name=order-route

# 3. ติด Plugin rate-limiting บน Service
curl -s -X POST http://localhost:8001/services/order-service/plugins \
  -d name=rate-limiting \
  -d config.minute=100 \
  -d config.hour=1000 \
  -d config.policy=local

# 4. ติด Plugin JWT authentication บน Route
curl -s -X POST http://localhost:8001/routes/order-route/plugins \
  -d name=jwt

# 5. สร้าง Consumer และ JWT credential
curl -s -X POST http://localhost:8001/consumers \
  -d username=mobile-app

curl -s -X POST http://localhost:8001/consumers/mobile-app/jwt \
  -d algorithm=HS256 \
  -d secret=my-super-secret-key

# 6. ทดสอบ — ต้องส่ง JWT token
curl -H "Authorization: Bearer " \
  http://localhost:8000/api/orders

decK — Declarative Config (แนะนำสำหรับ Production)

📌
decK (Declarative Kong) คือ CLI tool สำหรับ sync config จาก YAML file ไปยัง Kong — เหมือน Terraform แต่สำหรับ Kong โดยเฉพาะ เหมาะกับ GitOps workflow
kong.yaml — full declarative config YAML 
_format_version: "3.0"
_transform: true

# ── Services ──────────────────────────────────────
services:
  - name: order-service
    url: http://order-service:8080
    connect_timeout: 5000
    read_timeout: 30000
    write_timeout: 30000
    routes:
      - name: order-routes
        paths:
          - /api/orders
        methods:
          - GET
          - POST
          - PUT
          - DELETE
        strip_path: false
        preserve_host: false
    plugins:
      - name: rate-limiting
        config:
          minute: 100
          hour: 1000
          policy: redis
          redis_host: redis
          redis_port: 6379
      - name: prometheus
        config:
          status_code_metrics: true
          latency_metrics: true

  - name: user-service
    url: http://user-service:8081
    routes:
      - name: user-routes
        paths:
          - /api/users
        methods:
          - GET
          - POST
        strip_path: false
    plugins:
      - name: jwt
        config:
          secret_is_base64: false
          claims_to_verify:
            - exp

# ── Global Plugins ──────────────────────────────
plugins:
  - name: cors
    config:
      origins:
        - "https://myapp.com"
        - "https://admin.myapp.com"
      methods:
        - GET
        - POST
        - PUT
        - DELETE
        - OPTIONS
      headers:
        - Authorization
        - Content-Type
      exposed_headers:
        - X-Request-Id
      max_age: 3600
      credentials: true

  - name: opentelemetry
    config:
      endpoint: http://otel-collector:4318/v1/traces
      resource_attributes:
        service.name: kong-gateway
      propagation:
        default_format: w3c

# ── Consumers ──────────────────────────────────
consumers:
  - username: mobile-app
    jwt_secrets:
      - algorithm: HS256
        secret: "${MOBILE_APP_JWT_SECRET}"  # ใช้ env var ไม่ hardcode!
    plugins:
      - name: rate-limiting
        config:
          minute: 200   # consumer นี้ได้ limit พิเศษ
          policy: local

  - username: partner-api
    keyauth_credentials:
      - key: "${PARTNER_API_KEY}"
คำสั่ง decK bash 
# ติดตั้ง decK
brew install deck          # macOS
# หรือ download binary จาก github.com/kong/deck

# Sync config ไปยัง Kong (diff แล้ว apply)
deck sync --kong-addr http://localhost:8001 --state kong.yaml

# Dry-run ดูว่าจะเปลี่ยนอะไรบ้าง ก่อน sync จริง
deck diff --kong-addr http://localhost:8001 --state kong.yaml

# Export config ปัจจุบันจาก Kong เป็น YAML
deck dump --kong-addr http://localhost:8001 --output-file kong-backup.yaml

# Validate YAML ก่อน sync
deck validate --state kong.yaml

# Reset Kong ทั้งหมด (ระวัง!)
deck reset --kong-addr http://localhost:8001

☸️ Kong Ingress Controller (KIC)

ใน Kubernetes ใช้ Kong Ingress Controller ที่แปลง Kubernetes resources (Ingress, HTTPRoute, CRDs) เป็น Kong config อัตโนมัติ — ไม่ต้องใช้ Admin API โดยตรง

วิธีติดตั้ง KIC ด้วย Helm
ติดตั้ง Kong Ingress Controller bash 
# เพิ่ม Helm repo
helm repo add kong https://charts.konghq.com
helm repo update

# ติดตั้ง KIC (DB-less mode — แนะนำสำหรับ K8s)
helm install kong kong/ingress \
  --namespace kong \
  --create-namespace \
  --set gateway.env.database=off \
  --set gateway.env.router_flavor=expressions

# ดู pods
kubectl get pods -n kong

# ดู LoadBalancer IP
kubectl get svc -n kong kong-gateway-proxy

    konghq.com/preserve-host: "false"

  ingressClassName: kong

          - path: /api/orders
            pathType: Prefix
            backend:
              service:
                name: order-service
                port:
                  number: 8080

apiVersion: configuration.konghq.com/v1

  name: mobile-app

    kubernetes.io/ingress.class: kong

  - mobile-app-jwt-secret   # ชี้ไป Secret

🐹 Go Service + Kong Integration

ตัวอย่าง Go microservice ที่ทำงานร่วมกับ Kong — service ไม่ต้องรู้เรื่อง auth หรือ rate limiting เลย Kong จัดการให้ทั้งหมด

order-service/main.go — Go service ที่ทำงานหลัง Kong Go 
package main

import (
	"encoding/json"
	"log/slog"
	"net/http"
	"os"
	"time"
)

type Order struct {
	ID        string    `json:"id"`
	UserID    string    `json:"user_id"`
	Total     float64   `json:"total"`
	Status    string    `json:"status"`
	CreatedAt time.Time `json:"created_at"`
}

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	mux := http.NewServeMux()

	mux.HandleFunc("GET /api/orders", func(w http.ResponseWriter, r *http.Request) {
		// Kong inject consumer info เป็น header ให้อัตโนมัติ
		consumerID := r.Header.Get("X-Consumer-Id")
		consumerUsername := r.Header.Get("X-Consumer-Username")

		logger.Info("list orders",
			"consumer_id", consumerID,
			"consumer_username", consumerUsername,
			"request_id", r.Header.Get("X-Request-Id"), // Kong inject
		)

		orders := []Order{
			{ID: "ord-1", UserID: consumerID, Total: 299.99, Status: "pending", CreatedAt: time.Now()},
			{ID: "ord-2", UserID: consumerID, Total: 149.00, Status: "shipped", CreatedAt: time.Now().Add(-24 * time.Hour)},
		}

		w.Header().Set("Content-Type", "application/json")
		json.NewEncoder(w).Encode(orders)
	})

	mux.HandleFunc("POST /api/orders", func(w http.ResponseWriter, r *http.Request) {
		var req struct {
			Items []struct {
				ProductID string  `json:"product_id"`
				Qty       int     `json:"qty"`
				Price     float64 `json:"price"`
			} `json:"items"`
		}

		if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
			http.Error(w, `{"error":"invalid body"}`, http.StatusBadRequest)
			return
		}

		consumerUsername := r.Header.Get("X-Consumer-Username")
		order := Order{
			ID:        "ord-" + time.Now().Format("20060102150405"),
			UserID:    consumerUsername,
			Total:     calculateTotal(req.Items),
			Status:    "pending",
			CreatedAt: time.Now(),
		}

		logger.Info("order created",
			"order_id", order.ID,
			"total", order.Total,
			"consumer", consumerUsername,
		)

		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusCreated)
		json.NewEncoder(w).Encode(order)
	})

	// Health check endpoint — Kong ใช้ probe นี้
	mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
	})

	addr := ":8080"
	logger.Info("order service starting", "addr", addr)

	if err := http.ListenAndServe(addr, mux); err != nil {
		logger.Error("server failed", "err", err)
		os.Exit(1)
	}
}

func calculateTotal(items []struct {
	ProductID string  `json:"product_id"`
	Qty       int     `json:"qty"`
	Price     float64 `json:"price"`
}) float64 {
	var total float64
	for _, item := range items {
		total += item.Price * float64(item.Qty)
	}
	return total
}

Custom Go Plugin

custom-plugin/main.go — Go Plugin ด้วย Kong PDK Go 
// Kong Go Plugin Server — รัน external process ที่ Kong เรียกผ่าน RPC
// go get github.com/Kong/go-pdk

package main

import (
	"fmt"
	"time"

	"github.com/Kong/go-pdk"
	"github.com/Kong/go-pdk/server"
)

// Config กำหนด schema ของ plugin config
type Config struct {
	HeaderName string `json:"header_name"`
	TeamName   string `json:"team_name"`
}

func New() interface{} {
	return &Config{}
}

// Access phase — รันก่อน forward ไป upstream
func (c *Config) Access(kong *pdk.PDK) {
	// เพิ่ม custom header ที่ upstream จะได้รับ
	headerName := c.HeaderName
	if headerName == "" {
		headerName = "X-Team"
	}

	kong.Request.SetHeader(headerName, c.TeamName)
	kong.Request.SetHeader("X-Gateway-Time", fmt.Sprintf("%d", time.Now().UnixMilli()))

	// ดึงข้อมูล consumer จาก Kong
	consumer, err := kong.Client.GetConsumer()
	if err == nil {
		kong.Request.SetHeader("X-Consumer-Team", c.TeamName+":"+consumer.Username)
	}
}

// Response phase — รันก่อนส่ง response กลับ client
func (c *Config) Response(kong *pdk.PDK) {
	kong.Response.SetHeader("X-Served-By", "kong-"+c.TeamName)
}

func main() {
	// Version ของ plugin — เพิ่มทุกครั้งที่ config schema เปลี่ยน
	server.StartServer(New, "1.0.0", 1000)
}
