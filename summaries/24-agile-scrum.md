## เนื้อหาหลัก

### 1. Agile คืออะไร?
- แนวคิด (mindset) สำหรับสร้างผลิตภัณฑ์ท่ามกลางความไม่แน่นอน
- ทำงานเป็นรอบสั้น → ส่งของที่ใช้ได้ → รับฟีดแบ็ก → ปรับ
- **Agile vs Waterfall:** วางแผนทยอย vs วางทั้งหมดตอนต้น, ส่งบ่อย vs ส่งครั้งเดียว, ต้อนรับการเปลี่ยน vs ต่อต้าน
- Agile คือ mindset; Scrum/Kanban/XP/SAFe คือเฟรมเวิร์กที่นำไปใช้

### 2. Agile Manifesto — 4 ค่านิยม (เห็นคุณค่าทั้งสองฝั่ง แต่เอนซ้าย)
1. **คนและการมีปฏิสัมพันธ์** เหนือกว่า กระบวนการและเครื่องมือ
2. **ซอฟต์แวร์ที่ใช้งานได้** เหนือกว่า เอกสารที่ครบถ้วน
3. **การร่วมมือกับลูกค้า** เหนือกว่า การต่อรองสัญญา
4. **การตอบสนองต่อการเปลี่ยนแปลง** เหนือกว่า การทำตามแผน
- หลักการ 12 ข้อ: ส่งเร็ว/บ่อย, ต้อนรับการเปลี่ยน, จังหวะงานที่ยั่งยืน, ทบทวน/ปรับสม่ำเสมอ

### 3. Scrum Framework
- ส่งมอบเป็นรอบความยาวคงที่ = **Sprint** (1–4 สัปดาห์)
- 3 เสาหลัก: **Transparency → Inspection → Adaptation** (empirical control)
- โครงสร้าง: 3 บทบาท · 3 อาร์ทิแฟกต์ · 5 อีเวนต์

### 4. 3 บทบาท (Roles)
| บทบาท | รับผิดชอบ | สรุป |
|-------|-----------|------|
| **Product Owner** | "อะไร" (value) | เป็นเจ้าของ + จัดลำดับ Product Backlog, เสียงเดียวของลูกค้า |
| **Scrum Master** | "กระบวนการ" | servant-leader/โค้ช, กำจัดอุปสรรค, อำนวยอีเวนต์ — ไม่ใช่หัวหน้า |
| **Developers** | "การสร้าง" | สร้าง/เทสต์/ส่ง Increment, ประเมินงาน, จัดการตัวเอง |
- **ไม่มี project manager** ใน Scrum

### 5. 3 อาร์ทิแฟกต์ (Artifacts) + commitment
| Artifact | คำอธิบาย | Commitment |
|----------|----------|------------|
| **Product Backlog** | รายการเดียวจัดลำดับของทุกอย่างที่ผลิตภัณฑ์ต้องการ | Product Goal |
| **Sprint Backlog** | งานที่รับมาทำใน Sprint นี้ + แผน | Sprint Goal |
| **Increment** | ก้าวที่ใช้ได้และ "Done" | Definition of Done |
- **User Story:** As a [user], I want [goal], So that [value] + acceptance criteria
- **INVEST:** Independent, Negotiable, Valuable, Estimable, Small, Testable

### 6. 5 อีเวนต์ (Events) — ทุกอันมี time-box
| อีเวนต์ | Time-box | จุดประสงค์ |
|---------|----------|-----------|
| **Sprint** | 1–4 สัปดาห์ | กล่องหลัก ผลิต Done Increment, เริ่มใหม่ทันทีที่จบ |
| **Sprint Planning** | ≤ 8h | ตอบ Why (Goal) / What (items) / How (plan) |
| **Daily Scrum** | 15 min | ซิงก์ของ Developers, วางแผนวันใหม่ — ไม่ใช่รายงานหัวหน้า |
| **Sprint Review** | ≤ 4h | โชว์ Increment ให้ stakeholder, รับฟีดแบ็ก, ปรับ backlog |
| **Sprint Retrospective** | ≤ 3h | ทีมตรวจตัวเอง → ปรับปรุงรูปธรรม Sprint ถัดไป |
- time-box = เพดานสูงสุด ไม่ใช่เป้าหมาย

### 7. การประเมินและติดตาม
- **Story Points** = ความพยายามเชิงเปรียบเทียบ (ไม่ใช่ชั่วโมง) รวมความซับซ้อน+ความไม่แน่นอน+ปริมาณ
- **Planning Poker** สเกลฟีโบนักชี (1,2,3,5,8,13,21,?) — ช่องกว้างขึ้นโดยตั้งใจ
- **Velocity** = ค่าเฉลี่ยแต้ม/Sprint → ใช้พยากรณ์ (ห้ามเอามาเทียบทีม/เป็นเป้า)
- **Burndown chart** = งานคงเหลือเทียบเส้นอุดมคติ

### 8. Scrum Board
- คอลัมน์ **To Do → In Progress → Done** ทำ Sprint Backlog ให้มองเห็นได้
- การ์ด Done ต้องผ่าน Definition of Done — "เกือบเสร็จ" ไม่นับ
- WIP limit ยืมมาจาก Kanban

### 9. กับดัก (Anti-patterns)
- **Water-Scrum-Fall** — มี Sprint แต่สเปกใหญ่ตอนต้น+release ก้อนเดียวตอนจบ
- **Velocity เป็นเป้า** — ทำให้ประเมินเฟ้อ/ลัดขั้นตอน
- **Daily เป็นรายงานสถานะ** ให้หัวหน้า
- **ข้าม Retro** — ไม่มีการพัฒนา
- **เปลี่ยน Sprint Goal กลางทาง** — ทำลายโฟกัส
- **ไม่นิยาม Done** — บั๊กหลุด

## ประเด็นสำคัญที่ต้องจำ

> แก่นของ Scrum ไม่ใช่พิธีกรรม แต่คือ **ลูปฟีดแบ็ก** — ทุก Sprint ส่งของจริง เรียนรู้ และเก่งขึ้นทีละนิด
