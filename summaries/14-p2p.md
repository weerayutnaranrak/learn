# 14 — Peer-to-Peer (P2P)

**ไฟล์:** `14-p2p.html` | **หมวด:** Distributed & Communication Patterns

## สิ่งที่จะได้เรียน

ไม่มี Central Server — ทุก Node เป็นทั้ง Client และ Server BitTorrent, Blockchain, WebRTC

---

## เนื้อหาหลัก

### 1. P2P คืออะไร?
- ทุก node มีสิทธิ์เท่ากัน — ไม่มี master/slave
- Node แต่ละตัวเป็นทั้ง client (ขอข้อมูล) และ server (ให้ข้อมูล)
- ไม่มี single point of failure

### 2. ประเภทของ P2P Networks

| ประเภท | ตัวอย่าง | คำอธิบาย |
|--------|---------|----------|
| **Unstructured** | Gnutella | Flood query ทั้ง network |
| **Structured (DHT)** | BitTorrent, Kademlia | ค้นหา efficient ด้วย DHT |
| **Hybrid** | Napster (เดิม) | มี index server แต่ transfer ตรง |

### 3. Core Concepts

| Concept | คำอธิบาย |
|---------|----------|
| **DHT (Distributed Hash Table)** | Lookup table กระจายอยู่ทั้ง network — `key → node` |
| **Node ID & Routing** | แต่ละ node มี ID — route ไปหา node ที่ใกล้ key |
| **Peer Discovery** | หา nodes อื่นผ่าน bootstrap nodes หรือ mDNS |
| **Data Replication** | เก็บข้อมูลซ้ำหลาย nodes ป้องกัน node ออก |
| **Churn** | nodes เข้า/ออก network ตลอดเวลา |
| **NAT Traversal** | เชื่อม nodes ที่อยู่หลัง NAT/Firewall |
| **Sybil Attack** | node ปลอมสร้างหลาย identity — ต้องมี PoW/PoS ป้องกัน |
| **Eventual Consistency** | ข้อมูลกระจายไม่ sync ทันที |

### 4. ตัวอย่างในชีวิตจริง
- **BitTorrent** — File sharing ด้วย DHT
- **Bitcoin/Ethereum** — Blockchain consensus
- **IPFS** — Content-addressable storage
- **WebRTC** — Browser-to-browser video/audio
- **Tor** — Anonymous routing

### 5. ตัวอย่าง Code Go
- Simple TCP P2P node ที่ dial หา peers
- DHT-like routing table
- Gossip protocol สำหรับ broadcast message

### 6. P2P ใน Browser — WebRTC Pattern

| Component | หน้าที่ |
|-----------|---------|
| **STUN Server** | ค้นหา public IP ของ peer หลัง NAT |
| **TURN Server** | Relay server เมื่อ direct connection ไม่ได้ |
| **Signaling Server** | แลก SDP/ICE candidates (WebSocket) |
| **Data Channel** | ส่ง data โดยตรงระหว่าง browsers |

### 7. เมื่อไหร่ควรใช้ P2P?

**เหมาะกับ:**
- ต้องการ decentralized ไม่มี central authority
- File distribution ขนาดใหญ่
- Real-time peer communication (WebRTC)

**ระวัง:**
- Debug ยากมาก
- Security ซับซ้อน (Sybil, Eclipse attacks)
- ไม่เหมาะกับ latency-sensitive applications
