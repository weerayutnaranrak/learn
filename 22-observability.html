Observability

3 pillars — Logs, Metrics, Traces — know what your system is doing without guessing, using structured logging, Prometheus and OpenTelemetry3 pillars — Logs, Metrics, Traces — รู้ว่าระบบทำอะไรอยู่ โดยไม่ต้องเดา ด้วย structured logging, Prometheus, และ OpenTelemetry

🔭 3 Pillars of Observability
Each pillar answers a different question — use all three together to fully understand the systemแต่ละ pillar ตอบคำถามต่างกัน — ใช้ร่วมกันถึงจะเข้าใจระบบได้สมบูรณ์
📄
Logs
Records events that happened — "WHAT happened"
Good: detailed debugging
Limit: high volume → costly, must be searchedบันทึกเหตุการณ์ที่เกิดขึ้น — "WHAT happened"
ดี: debug รายละเอียด
ข้อจำกัด: มาก → แพง, ต้องค้นหา
📊
Metrics
Aggregated numbers measured continuously — "HOW MUCH"
Good: alerts, dashboards, trends
Limit: tells you something's wrong, not whyตัวเลขสรุปที่วัดต่อเนื่อง — "HOW MUCH"
ดี: alert, dashboard, trend
ข้อจำกัด: รู้ว่าผิดแต่ไม่รู้ทำไม
🔗
Traces
Follows a request across services — "WHERE slow"
Good: find bottlenecks in a distributed system
Limit: overhead, requires instrumentationติดตาม request ข้าม service — "WHERE slow"
ดี: หา bottleneck ใน distributed system
ข้อจำกัด: overhead, ต้อง instrument
What each pillar answers: Logs → "Why did order #123 fail?"  |  Metrics → "What's the error rate this hour?"  |  Traces → "The request is slow — which service is slow?"คำถามที่แต่ละ pillar ตอบ: Logs → "ทำไม order #123 ถึงล้มเหลว?"  |  Metrics → "error rate ชั่วโมงนี้เป็นเท่าไหร่?"  |  Traces → "request ช้า — ช้าที่ service ไหน?"

// ── Logger Middleware: ใส่ request fields ให้ทุก log ────────
func LoggingMiddleware(logger *slog.Logger) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            start := time.Now()

            // สร้าง request-scoped logger พร้อม default fields
            reqLogger := logger.With(
                slog.String("trace_id",   r.Header.Get("X-Trace-ID")),
                slog.String("method",     r.Method),
                slog.String("path",       r.URL.Path),
                slog.String("user_agent", r.UserAgent()),
            )

            // ใส่ logger ใน context
            ctx := context.WithValue(r.Context(), logKey, reqLogger)
            rw  := &responseWriter{ResponseWriter: w}

            next.ServeHTTP(rw, r.WithContext(ctx))

            reqLogger.Info("request_completed",
                slog.Int("status",  rw.status),
                slog.Int64("ms",    time.Since(start).Milliseconds()),
                slog.Int("bytes",   rw.bytes),
            )
        })
    }
}

// ดึง logger จาก context ใน handler/service
func logFromCtx(ctx context.Context) *slog.Logger {
    if l, ok := ctx.Value(logKey).(*slog.Logger); ok {
        return l
    }
    return slog.Default()
}

// ── Log Levels ที่ถูกต้อง ─────────────────────────────────
// DEBUG: developer detail — ปิดใน production
logger.Debug("cache_miss", slog.String("key", key))

// INFO: normal business event — order placed, user login

// WARN: unexpected แต่ recover ได้ — retry, fallback

// ERROR: ต้องดูแล — db error, external API fail
logger.Error("db_query_failed",
    slog.String("query", query),
    slog.String("error", err.Error()),

// ── RED Method: Rate, Errors, Duration ───────────────────────
// 3 metrics ที่สำคัญที่สุดสำหรับ service

var (
    // Rate: จำนวน request ต่อวินาที
    httpRequestsTotal = prometheus.NewCounterVec(
        prometheus.CounterOpts{
            Name: "http_requests_total",
            Help: "Total HTTP requests",
        },
        []string{"method", "path", "status"},
    )

    // Duration: latency distribution
    httpDuration = prometheus.NewHistogramVec(
        prometheus.HistogramOpts{
            Name:    "http_request_duration_seconds",
            Help:    "HTTP request duration",
            Buckets: []float64{.005, .01, .025, .05, .1, .25, .5, 1, 2.5, 5},
        },
        []string{"method", "path"},
    )

    // Business metric: order revenue
    orderRevenue = prometheus.NewCounterVec(
        prometheus.CounterOpts{
            Name: "order_revenue_baht_total",
            Help: "Total revenue from placed orders in Baht",
        },
        []string{"payment_method"},
    )

    // Gauge: active goroutines
    activeWorkers = prometheus.NewGauge(prometheus.GaugeOpts{
        Name: "worker_pool_active_workers",
        Help: "Number of currently active workers",
    })
)

func init() {
    prometheus.MustRegister(httpRequestsTotal, httpDuration,
        orderRevenue, activeWorkers)
}

// ── Middleware: record ทุก HTTP request ───────────────────────
func MetricsMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        rw    := &responseWriter{ResponseWriter: w, status: 200}

        next.ServeHTTP(rw, r)

        duration := time.Since(start).Seconds()
        status   := strconv.Itoa(rw.status)

        httpRequestsTotal.WithLabelValues(r.Method, r.URL.Path, status).Inc()
        httpDuration.WithLabelValues(r.Method, r.URL.Path).Observe(duration)
    })
}

🔗 Distributed Tracing — OpenTelemetry
Follow a request across many services using one shared trace_idติดตาม request ข้ามหลาย service ด้วย trace_id เดียวกัน
Problem: a user reports checkout is slow — there are 5 services in the path and you don't know where the slowdown is; each service's logs are viewed separately
Trace: every request carries the same trace_id throughout — each service creates a span saying what it did and when it started/ended, giving you a waterfall diagramปัญหา: user report ว่า checkout ช้า — มี 5 service ในเส้นทาง ไม่รู้ว่าช้าที่ไหน logs แต่ละ service ดูแยกกัน
Trace: ทุก request ได้ trace_id เดียวกันตลอด — แต่ละ service สร้าง span บอก ว่าทำอะไร เริ่ม-จบตอนไหน ทำให้เห็น waterfall diagram

// ── Setup: init tracer ──────────────────────────────────────
func initTracer(serviceName string) (*sdktrace.TracerProvider, error) {
    exporter, err := otlptracehttp.New(context.Background(),
        otlptracehttp.WithEndpoint("otel-collector:4318"),
        otlptracehttp.WithInsecure(),
    )
    if err != nil { return nil, err }

    tp := sdktrace.NewTracerProvider(
        sdktrace.WithBatcher(exporter),
        sdktrace.WithResource(resource.NewWithAttributes(
            semconv.SchemaURL,
            semconv.ServiceName(serviceName),
            semconv.ServiceVersion("1.0.0"),
        )),
        sdktrace.WithSampler(sdktrace.ParentBased(
            sdktrace.TraceIDRatioBased(0.1), // sample 10%
        )),
    )
    otel.SetTracerProvider(tp)
    otel.SetTextMapPropagator(propagation.TraceContext{})
    return tp, nil
}

// ── HTTP Middleware: ส่งและรับ trace context ─────────────────
func TracingMiddleware(next http.Handler) http.Handler {
    return otelhttp.NewHandler(next, "http_server",
        otelhttp.WithTracerProvider(otel.GetTracerProvider()),
    )
}

// ── Instrument business logic ─────────────────────────────
var tracer = otel.Tracer("order-service")

func (s *OrderService) PlaceOrder(ctx context.Context, o Order) error {
    // สร้าง span ครอบ operation
    ctx, span := tracer.Start(ctx, "OrderService.PlaceOrder",
        trace.WithAttributes(
            attribute.String("order.id",   o.ID),
            attribute.Float64("order.total", o.Total),
        ),
    )
    defer span.End()

    // nested span สำหรับ DB operation
    ctx, dbSpan := tracer.Start(ctx, "OrderRepository.Save")
    if err := s.repo.Save(ctx, o); err != nil {
        dbSpan.RecordError(err)
        dbSpan.SetStatus(codes.Error, err.Error())
        dbSpan.End()
        span.RecordError(err)
        return err
    }
    dbSpan.End()

    // span สำหรับ outgoing HTTP call
    ctx, notifySpan := tracer.Start(ctx, "NotificationService.Notify")
    s.notifier.Notify(ctx, o) // trace context propagated via HTTP header
    notifySpan.End()

    span.SetAttributes(attribute.Bool("order.completed", true))
    return nil
}

// ── HTTP Client: propagate trace context ─────────────────────
func (n *HTTPNotifier) Notify(ctx context.Context, o Order) error {
    req, _ := http.NewRequestWithContext(ctx, "POST",
        "http://notification-svc/notify", encodeOrder(o))

    // inject trace context ใน header: traceparent: 00-{traceID}-{spanID}-01
    otel.GetTextMapPropagator().Inject(ctx, propagation.HeaderCarrier(req.Header))

    _, err := http.DefaultClient.Do(req)
    return err
}
Correlate all 3 pillars — trace_id links logs + traces + metricsCorrelate ทั้ง 3 pillars — trace_id เชื่อม logs + traces + metrics Go · Correlation 
// ── Middleware ที่รวม Logs + Traces + Metrics ─────────────────
func ObservabilityMiddleware(
    logger  *slog.Logger,
    metrics *Metrics,
) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            start := time.Now()

            // ดึง trace context จาก request
            ctx    := r.Context()
            span   := trace.SpanFromContext(ctx)
            traceID := span.SpanContext().TraceID().String()
            spanID  := span.SpanContext().SpanID().String()

            // สร้าง logger ที่มี trace_id ติดไปด้วย → correlate กับ trace
            reqLogger := logger.With(
                slog.String("trace_id", traceID),
                slog.String("span_id",  spanID),
                slog.String("path",     r.URL.Path),
            )
            ctx = context.WithValue(ctx, logKey, reqLogger)

            rw := &responseWriter{ResponseWriter: w, status: 200}
            next.ServeHTTP(rw, r.WithContext(ctx))

            duration := time.Since(start)

            // Log — มี trace_id
            reqLogger.Info("request",
                slog.Int("status", rw.status),
                slog.Int64("ms",   duration.Milliseconds()),
            )

            // Metric — label ด้วย status
            metrics.Duration.WithLabelValues(
                r.Method,
                strconv.Itoa(rw.status),
            ).Observe(duration.Seconds())

            // Span attribute — เชื่อม trace กับ log
            span.SetAttributes(
                attribute.Int("http.status_code", rw.status),
                attribute.Int64("http.duration_ms", duration.Milliseconds()),
            )
        })
    }
}

Observability ≠ Monitoring: monitoring is "knowing something is wrong" — observability is "knowing why it's wrong without adding more code". The difference lies in the cardinality of the data and the correlation across the systemObservability ≠ Monitoring: Monitoring คือ "รู้ว่าผิดพลาด" — Observability คือ "รู้ว่าทำไม ผิดพลาดโดยไม่ต้องแก้ code เพิ่ม" ต่างกันที่ cardinality ของ data และการ correlate ข้ามระบบ
